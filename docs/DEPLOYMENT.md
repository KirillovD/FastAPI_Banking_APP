# Public Demo Deployment

The portfolio demo is packaged as one Dockerized web service:

```text
Browser
   |
   v
Render web service
   |-- FastAPI API + Swagger
   |-- built React frontend
   |
   v
Persistent PostgreSQL
```

The recommended low-cost setup is:

- **Render** for the Docker web service;
- **Neon** for persistent PostgreSQL.

Render's free web-service filesystem is ephemeral, so do not rely on the local SQLite file for a public demo. The application accepts a normal PostgreSQL connection string and includes the Psycopg driver.

## 1. Create the PostgreSQL database

Create a Neon project and copy its PostgreSQL connection string.

You can paste the standard:

```text
postgresql://...
```

URL directly into `DATABASE_URL`. Application config normalizes it to the installed Psycopg SQLAlchemy driver automatically.

For the portfolio-sized demo, the database is small.

## 2. Generate the card-encryption key

Generate a Fernet key locally:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Keep the result private and use it for `ENCRYPTION_KEY`.

Changing this key later makes previously stored synthetic CVVs unreadable.

## 3. Deploy the Render Blueprint

The repository includes `render.yaml`.

In Render:

1. Create a new Blueprint.
2. Connect this repository.
3. Use branch `portfolio-v2`.
4. Render reads `render.yaml` and builds the root `Dockerfile`.
5. Supply the prompted environment values:
   - `DATABASE_URL`: Neon connection string
   - `ENCRYPTION_KEY`: Fernet key from step 2
   - `DEMO_USER_PASSWORD`: the public demo password you want to share

`SECRET_KEY` is generated by Render.

The Blueprint also configures:

- Frankfurt region;
- free web compute;
- `/health` health check;
- `AUTO_CREATE_SCHEMA=true`;
- `SEED_DEMO_DATA=true`;
- 20% synthetic APR;
- 3% / EUR 30 synthetic minimum-payment settings;
- Europe/Berlin business timezone.

## 4. Demo account

When `SEED_DEMO_DATA=true`, application startup idempotently creates:

```text
Email: demo@example.com
Password: value of DEMO_USER_PASSWORD
PIN: 1234
```

The seed includes:

- checking account;
- savings account;
- EUR 500 synthetic credit line;
- synthetic credit card;
- statement history;
- payment-history metrics;
- German merchant/card transactions;
- salary and transfer activity;
- spending analytics;
- an explainable synthetic credit score.

The seed runs only if `demo@example.com` does not already exist, so normal restarts do not duplicate data.

## 5. URLs

After deployment:

- `/` — React portfolio application
- `/docs` — Swagger/OpenAPI
- `/health` — health check

The production React build uses same-origin API calls. Local development still uses Vite's `/api` proxy to `127.0.0.1:8000`.

## 6. Build locally

Build the exact production image:

```bash
docker build -t aurelia-banking-lab .
docker run --rm -p 8000:8000 --env-file .env aurelia-banking-lab
```

Then open:

```text
http://localhost:8000/
```

## Scheduler note

The web container intentionally does **not** launch `scheduler.py`.

Credit scheduler semantics were repaired and tested separately, but there must be only one authoritative scheduler process. Running a scheduler inside every web instance would risk duplicate daily/monthly jobs if the web service scaled.

For the public portfolio demo, the seeded data already demonstrates statements, interest/grace state and credit metrics. If continuous scheduled credit processing is desired later, run `scheduler.py` as exactly one dedicated worker/process with the same database and environment configuration.

## Production disclaimer

This repository is a portfolio banking simulator.

It uses synthetic cards and a custom explainable demo credit score. It is not a real card issuer, payment processor, credit bureau, lending system, FICO implementation, or SCHUFA implementation.
